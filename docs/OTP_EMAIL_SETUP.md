# NilePay OTP sender

Set these values on the API host (MonsterASP), then restart/publish the API:

```dotenv
SMTP_HOST=smtp.gmail.com
SMTP_PORT=465
SMTP_USER=nilepay.customers@gmail.com
SMTP_PASS=<Google App Password generated by this Gmail account>
EMAIL_FROM="NilePay <nilepay.customers@gmail.com>"
RESEND_API_KEY=
```

Use the App Password for `nilepay.customers@gmail.com`, with 2-Step Verification enabled on that account. A password from the previous sender cannot authenticate the new account. Keep it in the host secrets/environment and never commit it. Local sender configurations changed from another account have their old SMTP password cleared deliberately.

The mailer currently tries Resend first, then Gmail SMTP. Leave `RESEND_API_KEY` empty when Gmail should send the message. A Gmail sender address cannot normally be verified as a sending domain on Resend.

Verify by requesting one merchant login/signup code using the website or APK after deployment. Check that the message arrives from NilePay at `nilepay.customers@gmail.com`; use API delivery logs for errors. Changing the public support email in the admin portal does not change SMTP credentials.

# Mobile payment feed

The merchant app now uses authenticated `GET /api/mobile/payments` with `status`, `search`, `limit`, and opaque `cursor` parameters. Publish the updated API before installing this APK. The feed combines merchant-owned checkout transactions and unresolved unmatched payment records. Filters and pagination run on the server, so they cover older records too. The APK displays server status; it never automatically confirms flagged payments. No schema migration is required.
